# Z-PRD 使用说明

## 最常用的说法

```text
Use $z-prd 帮我把这个想法整理成 PRD 和产品设计。
```

```text
用 $z-prd 从一句话需求到 UI 原型计划，先给我可评审版本。
```

```text
Use $z-prd 直接跑完，从需求到原型计划，不需要中途停。
```

## 推荐工作方式

1. 先给一句话想法或粗略背景。
2. 让 `$z-prd` 输出产品文档评审版。
3. 你确认或提出修改。
4. 再进入 UI 原型计划或研发交接。

## 适合输入

- “帮我做一个 XX 工具”
- “我要一个面向 XX 用户的 SaaS”
- “把这个需求写成 PRD”
- “从这个想法做产品设计”
- “这个功能进入 vibe coding 前帮我补齐需求”

## 不适合输入

- 只想改一个按钮颜色。
- 已经有完整技术方案，只需要执行代码改动。
- 只要竞品调研或市场研究，不需要 PRD/原型/交接。

## 评审点怎么回复

- 回复“继续”：进入 UI 原型计划。
- 回复“按这个做”：进入下一阶段。
- 直接提出修改点：回到产品文档修订。
- 回复“无需审核，直接跑完”：跳过默认评审点。
