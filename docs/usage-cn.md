# Z-PRD 使用说明

## 最常用的说法

```text
Use $z-prd 帮我把这个想法整理成 PRD 和产品设计。
```

```text
用 $z-prd 从一句话需求到 UI 原型计划，先给我可评审版本。
```

```text
Use $z-prd 直接跑完，从需求到原型计划，不需要中途停。
```

## 推荐工作方式

1. 先给一句话想法或粗略背景。
2. 让 `$z-prd` 输出产品文档评审版。
3. 你确认或提出修改。
4. 再进入 UI 原型计划或研发交接。

## 适合输入

- “帮我做一个 XX 工具”
- “我要一个面向 XX 用户的 SaaS”
- “把这个需求写成 PRD”
- “从这个想法做产品设计”
- “这个功能进入 vibe coding 前帮我补齐需求”

## 不适合输入

- 只想改一个按钮颜色。
- 已经有完整技术方案，只需要执行代码改动。
- 只要竞品调研或市场研究，不需要 PRD/原型/交接。

## 评审点怎么回复

- 回复“继续”：进入 UI 原型计划。
- 回复“按这个做”：进入下一阶段。
- 直接提出修改点：回到产品文档修订。
- 回复“无需审核，直接跑完”：跳过默认评审点。

## 设计输出怎么选

产品方案确认后，`Z-PRD` 会问是否继续输出设计落地材料。你可以这样回复：

- “不继续，先到这里”：停在当前 PRD/产品设计。
- “输出低保真”：生成页面清单、流程、线框说明和状态矩阵。
- “给墨刀用”：生成适合墨刀原型搭建的页面、交互、文案和流程清单。
- “给蓝湖交付”：生成标注、资产、组件、间距、颜色、验收说明。
- “给 Figma/MasterGo”：生成 frame 规划、组件映射、token 表和研发模式说明。
- “做可运行原型”：进入 HTML/React 原型输出。

如果你已经登录墨刀、蓝湖等平台，并希望上传，明确说“上传到 XX 项目”。上传前会再次确认具体目标和内容。

选择后会继续输出对应交付包，不会只停在选项层。例如：

- 选墨刀：直接给页面分组、流程连线、交互说明、状态矩阵、上传清单。
- 选蓝湖：先问是否有团队标准样式；没有则按通用规范给标注、组件、资产和验收点。
- 选 Figma/MasterGo/Pixso：给 frame、组件、token、prototype、Dev Mode 说明。
- 选可运行原型：进入实际 HTML/React 原型规划或实现。
